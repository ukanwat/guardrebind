# Nothing to See Here: Fooling LLM Safety Guards into Judging the Wrong Text

Code, data and every raw score for the paper (`paper/main.pdf`, source in `paper/`).

LLM safety guards receive the content they review by plain string interpolation into
their grading prompt, so content that imitates the guard's own prompt format can open a
second, forged grading task with a harmless decoy document, which the guard then grades
instead of the real content (*target rebinding*). Appending such a forged task clears
Shieldstral-1.0-3B on all 75 pre-registered held-out AdvBench requests it flags,
transfers to gpt-oss-safeguard-20B and Llama Guard 4, and in our benchmark,
**GuardRebind** (52 attack families, 5 controls), the strongest family clears 93-100% of
flagged items on each of five guards. Segment-max self-distillation trains the guard to
score content at least as high as its most harmful part and cuts bypass on held-out
attacks from 75% to about 1%, but a score-guided adaptive attacker still clears the
trained guard on 94% of items, more than half of them with no forged structure at all.

The attack is described in prose here on purpose. The payloads are generated by
`src/attacks.py` (confirmatory study) and `src/bench/attacks_grammar.py` (benchmark), and
are listed in the paper's appendix.

(gitignored, about 40k items, split 60/10/30 by a hash of the normalised text):

```
uv run python -m src.bench.data            # build or read the cache, print counts
```

## Reproduce

design before any test-split run. Plots need matplotlib, which is not in the lock: the

runs on Llama Guard 3 and Qwen3Guard, the GCG table and the forgery controls:

```
PART=main sh scripts/queue_fix_full.sh       # also: PART=generality, PART=seeds
```

Round 2 gives the paper's main defense numbers (held-out decoys):

```
sh scripts/queue_round2.sh

```

The individual steps, as the queue runs them:

```
uv run --frozen python -m src.fix.distill build --out data/fix/full_r2.jsonl --max-items 5000 --per-item 2 --decoy-split train
uv run --frozen python -m src.fix.distill build --out data/fix/clean_copy_r2.jsonl --max-items 5000 --per-item 2 \
  --mode clean_copy --decoy-split train --cache data/fix/full_r2.teacher_cache.jsonl
uv run --frozen python -m src.fix.distill train --data data/fix/full_r2.jsonl --fmt stock   --seed 0 --out models/fix/r2_t_seed0
uv run --frozen python -m src.fix.distill train --data data/fix/full_r2.jsonl --fmt bounded --seed 0 --out models/fix/r2_bt_seed0
uv run --frozen python -m src.fix.evaluate --cond T --adapter models/fix/r2_t_seed0 --split test --allow-test \
  --decoy-split fixed,heldout --out results/fix/r2_test_t_seed0.json        # also --cond base|B|detector|segmax_infer|BT
uv run --frozen python -m src.fix.adaptive --cond T --adapter models/fix/r2_t_seed0 --split test --n 50 \
  --attack search --budget 300 --out results/fix/r2_adaptive_t_seed0_search.json
uv run --frozen python -m src.fix.adaptive --cond T --adapter models/fix/r2_t_seed0 --split test --n 50 \
  --attack structural --decoy-split heldout --out results/fix/r2_adaptive_t_seed0_structural_heldout.json
uv run --frozen python -m src.fix.adaptive --cond T --adapter models/fix/r2_t_seed0 --split test --n 20 \
  --attack gcg --steps 250 --batch 32 --out results/fix/r2_adaptive_t_seed0_gcg.json
```

The plain-text control for the score-guided search is not in the queue. It was run
separately, on `--cond base` and on `--cond T --adapter models/fix/r2_t_seed0`:

```

  --attack search --budget 300 --null-search --out results/fix/r2_adaptive_t_seed0_search_null.json
```

To evaluate a released adapter without training, put it under `models/fix/` (see
"Released adapters") and run only the `evaluate` / `adaptive` lines.

## Hardware

- **Mac with Apple silicon (MPS).** The confirmatory study and the benchmark ran on an
  M4 Max. `scripts/lib.sh` caps MPS memory, and `scripts/mem_guard.sh` pauses jobs when
  memory runs low. `scripts/supervisor.sh` plus the launchd template
  `scripts/io.guardpaper.supervisor.plist` rerun the queues after a crash. Every queue
  step resumes from what is already on disk.
- **A single 24GB CUDA GPU.** Training, test-split defense evaluation, adaptive attacks
  and mechanism runs used one RTX 4090. One training run of T or B+T takes about
  17 minutes (2,032 steps, LoRA rank 16, batch 8, max length 384). `scripts/pod/up.sh
  HOST PORT` copies the code to a Runpod pod and starts the queue. `scripts/pod/down.sh
  HOST PORT` copies results back, and `scripts/pod/run.sh` stops the pod when it is done
  or when it hits `MAX_HOURS`. The pod scripts expect your own SSH key and HF token; edit
  the key path in `up.sh`/`down.sh`.
- Run one GPU job at a time. The queues wait for each other.

## Earlier study

This repo started as the study behind the blog post
[A safety model will grade whichever text you show it last](https://utkarshkanwat.com/writing/safety-guards-wrong-document).
That writeup is in `ARTICLE.md` (`ARTICLE_alt.md` is an alternate draft), and its frozen
design is `PROTOCOL.md`, which the paper's Section 3 reuses as its confirmatory study. The
blog-era charts and CSVs (`results/chart_*.svg`, `results/fig_*.svg`,
`results/scores*.csv`, `results/confirm_{screen,supp}.csv`,
`results/openrouter_gpt_oss_safeguard.csv`) come from `src/charts.py`, `src/figures.py`
and `src/run.py`. `notes/prior-art.md` is the prior-art scan.
