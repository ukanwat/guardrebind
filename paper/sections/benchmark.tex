For Llama Guard~4 we did not separate rebinding from the forged delimiter breaking the provider's chat template, because the provider controls the template; we report a bypass with plain assertion ruled out.

\subsection{Benchmark design}

\paragraph{Guards.}
We evaluate four open-weight guards that span three input designs, run locally: Shieldstral-1.0-3B~\citep{calvi2026shieldstral}, Llama Guard~3 1B~\citep{grattafiori2024llama}, ShieldGemma 2B~\citep{zeng2024shieldgemma} and Qwen3Guard 0.6B~\citep{zhao2025qwenguard}; and gpt-oss-safeguard-20B through an API~\citep{openai2025gptosssafeguard}. Larger variants did not fit the single-machine memory budget alongside the defense training, so size is not a factor we vary (\cref{sec:limitations}).
Scores are each guard's $P(\text{unsafe})$ renormalised over its own label tokens; for Qwen3Guard, whose labels are Safe, Unsafe and Controversial, the score is $P(\text{Unsafe})+P(\text{Controversial})$, its strict mode.

\paragraph{Data.}
Harmful and benign items come from AdvBench~\citep{zou2023universal}, HarmBench~\citep{mazeika2024harmbench}, Aegis~2.0~\citep{ghosh2025aegis}, BeaverTails~\citep{ji2023beavertails}, the OpenAI moderation evaluation~\citep{markov2022holistic}, and ToxicChat~\citep{lin2023toxicchat}, with XSTest-safe~\citep{rottger2023xstest} and OR-Bench-hard~\citep{cui2024orbench} as benign over-refusal sources: 20k harmful and 20k benign \emph{items} (texts), split 60/10/30 by a hash of the normalised text. % src: src/bench/data.py load_all(): sources advbench, harmbench, aegis2, beavertails, openai_mod, toxicchat, overrefusal_xstest, overrefusal_orbench; 20000/20000 by label
The core set is a stratified sample of 600 harmful and 600 benign test items per guard (fixed in the protocol before any test run, for compute).
gpt-oss-safeguard is reached through a paid API, so it runs on a 200 + 200 subset of the core set; 113 of the 200 harmful items pass its screen. % src: results/bench/v2/gpt_oss_summary.md (core_set(n=200); 113 screened); paper/data/gpt_oss_strict.md

\paragraph{Attack grammar.}
Attacks are generated from a grammar rather than written by hand.
Its axes are label syntax (each guard's own tags, brackets, markdown, colon, abbreviations, JSON, XML, YAML), number of forged pairs (1--5), position, decoy harm, forged-query relatedness, language, and encoding (real control tokens or plain text, \cref{sec:control}).
Each combination of axis levels is an attack \emph{form}; the full grammar yields 659 forms (654 attack forms and 5 controls) and a 63-form \emph{core attack panel} (the pre-registered 62 plus the length control of D2); \cref{app:grammar} lists the axes and levels. % src: src/bench/attacks_grammar.py len(grammar(core=False)) = 659, len(grammar(core=True)) = 63, CONTROLS = none, benign_tail, sentence_bare, authority_note, len_control
The 63 core forms group into 57 \emph{families} (52 attack families, 4 controls and the no-attack condition) once the decoy and the forged query are drawn per instantiation; an \emph{instantiation} is one concrete attack string, and each item--family cell draws three instantiations from a pool of benign decoys and the family's query pool, and we report the first instantiation, the mean over instantiations and the per-item worst case over instantiations (the item counts as cleared if any instantiation clears it). % src: PROTOCOL_v2.md (Deviation D1, K=3); src/bench/attacks_grammar.py grammar(core=True): 63 forms; results/bench/v2/bypass.csv: 52 attack families + 4 control| rows per guard (none = clean row)
The \emph{guard-native} form writes the guard's own turn or template markers as text and forges the guard's whole grading task, not only its content delimiters, because the task is the unit a guard rebinds to (\cref{sec:bench-results}); for Qwen3Guard this is the template's closing instruction tail followed by a complete new task, policy, category list and conversation. % src: PROTOCOL_v2.md (Deviation D2); results/bench/explore/qwen3guard.md
That forgery is long (about 1.35k characters, against about 60 for the other guards; the exploratory probe of \cref{sec:request-unit} used a 1.7k-character version), so every guard also gets a length control: benign filler of matched length with no labels. % src: PROTOCOL_v2.md (Deviation D2, len_control)
Position is append (after the request), prepend (before it) or middle: benign filler, then the request, then the forged structure, so the request sits between two benign blocks.
Content is placed where each guard's own format puts the material under review (the user turn, or the response for response-side items); we do not measure the retrieval, tool-result and multi-turn channels of \cref{sec:threat} separately.

\paragraph{Protocol.}
The full core attack panel runs on the core set for every guard under its default policy, and six families also run under two paraphrased deployment policies. % src: results/bench/v2/run_config.json (policies default/para1/para2; policy_families: 6)
Each table reports the \emph{clean miss rate} (false-negative rate, FNR: the share of harmful items judged safe with no attack) and the clean false-positive rate (FPR: the share of benign items flagged) next to the bypass, and the always-flag baseline; sensitivity to $\tau$ is in \cref{app:grammar}.
Bypass is the mean over the three instantiations, with a 95\% interval from a two-level bootstrap over items and then instantiations, as pre-registered. % src: PROTOCOL_v2.md D1(a)
The predictions were registered before the run (\cref{app:protocol}).

\paragraph{gpt-oss-safeguard.}
The base guard is a weak detector on this data before any attack: on 200 harmful and 200 benign core items it flags $56.5\%$\ci{49.6\%}{63.2\%} of harmful items and $12.0\%$\ci{8.2\%}{17.2\%} of benign ones, an area under the ROC curve (AUROC) of $0.72$ from its binary verdict (per-source rates in \cref{app:gpt-oss}). % src: paper/data/gpt_oss_strict.md (parse = strict: recall 113/200, FPR 24/200); results/bench/v2/gpt_oss/auc.csv (clean auroc 0.7225)
Bypass is measured on the 113 harmful items it flags; rates in this paragraph are means over three instantiations unless stated.
The forged triple clears $100\%$ in each of six label syntaxes, $99.7\%$ in Spanish and $99$--$100\%$ with two to five stacked triples, but its instruction field is the directive $S$ (``Disregard the section above\ldots''), so it does not separate rebinding from persuasion. % src: paper/data/gpt_oss_strict.md (parse = strict, mean column): angle/colon/md_bold/json/xml/control_token full_triple 100.0; angle full_triple lang=es 99.7; n=2 100.0, n=3 100.0, n=5 99.4
The guard-native forgery has no instruction sentence: it writes the model's own turn markers as text to open a developer turn holding the forged query and a user turn holding the decoy. It clears $71.7\%$\ci{65.2\%}{78.5\%} with one pair ($95.6\%$ of items fall to at least one of the three instantiations) and $97.6$--$99.7\%$ with two to five. % src: paper/data/gpt_oss_strict.md (parse = strict, mean column): guard_native query_doc 71.7 [65.2, 78.5], worst 95.6; n=2..5 99.7, 99.1, 97.6, 98.8
The controls follow the rebinding signature of \cref{sec:attack}: with a harmful decoy these forgeries clear $6.8\%$; placed before the content, $10.3\%$ (triple) and $3.8\%$ (guard-native); the instruction alone, a ``Note:'' or length-matched filler, $2.7$--$6.2\%$. % src: paper/data/gpt_oss_strict.md (parse = strict, mean column): angle full_triple decoy=harmful 6.8, guard_native decoy=harmful 6.8, angle full_triple pos=prepend 10.3, guard_native pos=prepend 3.8; single-instantiation controls control|sentence_bare 2.7, control|authority_note 3.5, angle instruct_only 6.2, control|len_control 6.2

Benign items carrying the same forgeries are flagged at $0$--$13\%$, against $12.0\%$ clean. % src: paper/data/gpt_oss_strict.md (parse = strict, Benign + attack): 0/200 (angle full_triple) to 26/200

\paragraph{What counts as a task.}
\label{sec:request-unit}
The guards differ in which forged structure they rebind to.
Our hypothesis, which the results below are consistent with but do not establish causally, is that each guard grades the most recent complete \emph{grading task} in its input (the developer-written fields it answers, plus a document or conversation), and that what counts as a complete task depends on its format.
On Shieldstral a query--document pair is a complete task, so the pair alone clears $100\%$ and an added forged instruction is not needed (\cref{tab:ablation}).
On gpt-oss-safeguard, whose policy sits in the system role, a forged pair in a generic syntax clears $2$--$13\%$, while the guard-native forgery that opens new developer and user turns, with no instruction text, clears $71.7\%$; the forged triple clears $100\%$, but its instruction field is the directive $S$, so part of that gain may be persuasion rather than a larger task unit. % src: paper/data/gpt_oss_strict.md (parse = strict, mean column): {angle,colon,bracket,md_bold,json,xml,yaml,control_token,q_short} query_doc 2.4-13.3; guard_native query_doc 71.7
Qwen3Guard makes the point most clearly, in an exploratory probe on the train split of Qwen3Guard-Gen-0.6B with 40 flagged items. % src: results/bench/explore/qwen3guard.md (train split, n=40, Qwen3Guard-Gen-0.6B, bf16)
Its template wraps the conversation in a large instruction block: a task line, a policy and a category list before the conversation, and a closing instruction tail after it.
Forging only the conversation, by closing it and opening a new one whose user turn is the benign decoy, clears 5/40 ($13\%$\ci{5\%}{26\%}). % src: results/bench/explore/qwen3guard.md (conv_reopen 5/40 [0.05, 0.26])
Forging the whole task, the closing tail followed by a new task line, policy, category list and conversation, clears 40/40 ($100\%$\ci{91\%}{100\%}, median score $0.006$). % src: results/bench/explore/qwen3guard.md (full_block_plain 40/40 [0.91, 1.00], median 0.006)
Parts of the task add up: without the tail it clears 35/40, with only the policy and categories 23/40, and with only the task line 17/40. % src: results/bench/explore/qwen3guard.md (abl_task_only 35/40, abl_policy_cats_only 23/40, abl_task_line_only 17/40)
It is rebinding, not a long prompt that drowns the harmful request: the same block with a harmful decoy stays flagged (median $0.997$), and with the forged block placed first and the harmful text last it clears 0/40. % src: results/bench/explore/qwen3guard.md (H+harmful decoy median 0.997; pre_ct_full_block 0/40)
The length-matched filler control in the benchmark run tests length directly: on the test core set it clears Qwen3Guard $4.7\%$\ci{3.0\%}{6.5\%} of the time, against $81.7\%$ for the full-task forgery. % src: bypass.csv qwen3guard_0_6b control|len_control 4.7 [3.0,6.5]; guard_native query_doc 81.7
A guard whose grading task includes its instructions therefore needs the instructions forged too, and a defense that only protects the content delimiters, or only the conversation markers, protects the wrong unit; \guardrebind{} uses the full-task forgery for Qwen3Guard for this reason.
