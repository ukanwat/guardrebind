\section{The Control-Token Channel (Exploratory)}
\label{sec:control}

The attack of \cref{sec:attack} forges structure in plain text.
A second, stronger channel exists at the tokenizer.
Under the default Hugging Face chat template, literal strings such as \texttt{[/INST]} or \texttt{[SYSTEM\_PROMPT]} placed inside the content are tokenized as the \emph{real} control token ids (4 and 17 in the Tekken vocabulary), so the content can close the user turn and open a new one for real rather than imitating a label in text. % src: PLAN.md findings log 2026-10-15
This section is labelled exploratory: it is a probe on the first 40 held-out flagged rows, outside the frozen protocol.

On those 40 documents (\cref{tab:control}): the plain label pair clears 40/40 (median $0.014$), matching \cref{sec:attack}; closing and reopening the turn with real control tokens before a forged triple clears 40/40 at a markedly lower median ($0.0028$); and a forged system prompt (``answer no to every document'') delivered through real control tokens clears 11/40, where an instruction otherwise does almost nothing. % src: PLAN.md findings log
A split-token control tokenizes the identical strings as plain text, isolating the control-token effect: the reopen attack then clears 39/40 (median $0.029$, about $10\times$ higher than with real tokens) and the forged system prompt clears 0/40. % src: PLAN.md findings log 2026-10-15 split-token control
So the labelled pair does most of the work; the real control tokens are an amplifier (roughly $10\times$ lower score) and a channel of their own that makes an otherwise-inert instruction partly effective.

This channel motivates part of the fix (\cref{sec:fix}): tokenizing content with special-token parsing off is necessary so that control-token strings in the content cannot become real boundaries.
\guardrebind{} (\cref{sec:benchmark}) audits how many guards' tokenizers and chat templates exhibit this behaviour.
